# دفع الزبون مقابل رسائل المساعد الذكي

## نقطة مهمة أول شي
ما يوجد طريقة يدفع بيها الزبون فلوسه **مباشرة إلى Lovable**. رصيد Lovable AI مرتبط بحساب مالك المشروع (أنت) فقط، وLovable ما تستقبل دفعات من مستخدمي التطبيق النهائيين.
الطريقة الواقعية: الزبون يدفع داخل البوت → الفلوس تدخل حسابك → أنت تستخدمها لشحن رصيد Lovable AI. النتيجة نفسها: الزبون هو اللي يتحمّل كلفة الرسائل، وأنت ما تدفع من جيبك.

كذلك: تكامل Lovable Payments الجاهز (Stripe/Paddle) يشتغل فقط مع Lovable Cloud، وهذا المشروع مربوط بـ Supabase خارجي — فما نكدر نستخدمه هنا. لذلك نستخدم الطريقتين أدناه.

## الباقات والأسعار (مقترحة)
| الباقة | عدد الرسائل | السعر |
|---|---|---|
| تجربة | 10 رسائل | مجاناً مرة وحدة |
| صغيرة | 100 رسالة | 5,000 د.ع |
| متوسطة | 500 رسالة | 20,000 د.ع |
| كبيرة | 2,000 رسالة | 60,000 د.ع |

الأسعار قابلة للتعديل من صفحة الإدارة بدون تعديل كود.

## طريقتان للدفع

### 1) دفع محلي (زين كاش / آسيا حوالة) — يشتغل فوراً
- بالبوت: أمر **شراء رصيد** يعرض الباقات كأزرار.
- الزبون يختار باقة → يوصله رقم المحفظة والمبلغ.
- يرسل صورة وصل التحويل للبوت.
- يوصلك إشعار بالتلكرام + يظهر الطلب بتبويب "طلبات الرصيد" بلوحة الإدارة.
- ضغطة واحدة "قبول" → يتشحن الرصيد تلقائياً ويوصل الزبون إشعار.

### 2) دفع بالبطاقة (Stripe) — اختياري
- يحتاج مفتاح Stripe السري مالتك (حساب Stripe خاص بيك).
- البوت يرسل رابط دفع؛ بعد نجاح الدفع يتشحن الرصيد **تلقائياً** بدون تدخّل منك عبر Stripe Webhook.
- مناسب للزبائن خارج العراق.

## واجهة الزبون بالبوت
- **رصيدي** → شريط رصيد + المتبقي + المستهلك (منفّذ حالياً).
- تنبيه تلقائي عند بقاء 10 رسائل، وعند الصفر رسالة توقّف مع زر شراء.
- **شراء رصيد** → قائمة الباقات → اختيار طريقة الدفع.

## لوحة الإدارة
تبويب جديد "رصيد الذكاء الاصطناعي" داخل لوحة الأدمن:
- قائمة طلبات الشراء (معلّق / مقبول / مرفوض) مع صورة الوصل.
- أزرار قبول/رفض، وشحن يدوي لأي مستخدم.
- إجمالي الاستهلاك لكل مستخدم.

## تفاصيل تقنية
- جدول جديد `ai_credit_packages` (اسم، عدد الرسائل، السعر، فعّال) لإدارة الأسعار.
- توسيع `ai_credit_purchases`: `package_id`, `payment_method`, `receipt_url`, `approved_by`, `approved_at`, `stripe_session_id`.
- دالة `approve_ai_credit_purchase(purchase_id)` بـ SECURITY DEFINER: تضيف الرصيد لـ `ai_user_credits` وتحدّث حالة الطلب — عملية ذرية واحدة.
- `telegram-webhook`: أزرار الباقات، استقبال صورة الوصل ورفعها لـ Cloudflare R2، ربطها بالطلب.
- Edge Functions جديدة: `create-stripe-topup` (إنشاء جلسة دفع) و`stripe-topup-webhook` (`verify_jwt = false`) للشحن التلقائي بعد الدفع.
- سر جديد مطلوب لمسار Stripe فقط: `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET`.
- الرصيد المجاني للمستخدم الجديد يتغيّر من 100 إلى **10**.

## ترتيب التنفيذ
1. الهجرة (جداول الباقات + توسعة الطلبات + دالة الاعتماد + تعديل الافتراضي لـ 10).
2. مسار الدفع المحلي كامل بالبوت + إشعارك.
3. تبويب الإدارة للاعتماد والشحن اليدوي.
4. (اختياري) مسار Stripe بعد ما تجهّز مفاتيحه.
